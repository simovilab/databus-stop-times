bUCR — segment leaderboard

55-day corpus · day-grouped holdout (33 d / 5 d)

One row per stop-to-stop segment; target is the position-derived traversal time, so bUCR's offset timetable can't poison the labels. Only the geometry + kinematics + temporal models pull ahead of the schedule — the timetable itself already beats naive historical-mean and EWMA.

Test MAE by model · lower is better

datasets/bucr_segments_corpus.parquet · 17,499 segments, 40 CR-days, 21 legs

XGBoost leads at 33.4 s (R² 0.694); the two polyreg families are within ~2.5 s. The offset schedule sits at 51.6 s — better than historical-mean/EWMA but 35% behind the learned models.
02

bUCR — error grows predictably with horizon

stop-level, summed segments

Stop-level ETA is derived by summing predicted segment times over the remaining path. The advantage holds around 40% through five stops — the range that matters most to a waiting rider — and the error distribution is spike-plus-tail (Laplace-like), so the median rider sees far less than the mean.

XGBoost stop-level error vs stops ahead

MAE with p90 / p95 envelope, seconds

One stop out the median error is 17 s; even eight stops ahead the MAE (126 s) stays under the schedule's tail.

Leakage probe — the formulation is honest

roadmap 3.2 · shuffle-label control

Permute the target within train + val (features untouched, test untouched) and retrain. A model can then only learn noise, so its metrics must collapse to the naive constant-predictor reference. They do — while the real-label control reproduces the known result. No target is leaking through the features.

Real labels vs shuffled labels · test MAE

models/evaluation/leakage_probe.py · seed 42 · naive reference = 71.2 s

Shuffled-label MAE collapses to 72–70 s (R² ≈ 0) against the 71.2 s naive line, while the control holds at 33–36 s (R² 0.69/0.66). PASS

MBTA — how much history does a new agency need?

stop-level · routes 222/15/37 · global models

The dataset-size ablation that becomes a paper section. Four windows anchored at 2026-07-01; all five families trained on each. XGBoost wins at every size; both it and polyreg-time peak in R² around 15 days, then dip slightly at 28 (ordinary week-to-week variance in real data, not a regression).

05

MBTA — segment models vs the schedule

16-day corpus · day-grouped holdout

The MBTA segment reformulation at scale: 153,498 segments over a full 16-day window (routes 222/15/37), each sub-window matched to the static-GTFS snapshot in effect. Real GTFS trip IDs make the schedule baseline exact — the scheduled duration of each stop-to-stop segment, offset-invariant so a trip running late as a whole isn't penalised. Split is day-grouped (all 16 service-days usable) so whole trips stay in one split. (An agency GTFS-RT baseline isn't available offline — MBTA TripUpdates aren't archived yet; that comparator is live-only via etaval.)

Test MAE by model · lower is better

datasets/mbta_segments_corpus.parquet · test = 3 service-days, 28,346 segments

XGBoost leads at 27.5 s (R² 0.627), +44% over the 48.9 s schedule. Notably, per-segment historical_mean (33.7 s) is the strong runner-up — ahead of both polyreg families on MBTA, a different ordering than bUCR.

FIXED Weekday coverage. MBTA reuses one trip_id across every weekday, and the builder used to collapse a reused id into a single trip instance — dropping Tue–Thu repeats and leaving only ~10 effective service-days. 06

Hyperparameter tuning (Optuna)

50 trials/agency · tuned on val, tested once

Roadmap 5.1: the validation split was computed but never used, and every hyperparameter was hardcoded. A TPE study over the five XGBoost hyperparameters, scored on the validation split of each segment corpus and selecting the best config by val MAE — the test set is touched only once, for the chosen config. Every trial is recorded. Tuning helps both agencies, and the best configs differ sensibly by data volume.

Tuning cuts test MAE 9–11%: MBTA 27.5→25.0 s (R² 0.627→0.644), bUCR 33.5→29.9 s (R² 0.694→0.759).

Provenance & caveats

  • Numbers are rehearsal-corpus results measuring pipeline correctness and experimental design — not the transferable 90-day replication numbers (window 2026-08-14 → 2026-11-12).
  • bUCR and MBTA corpora differ in fix cadence (~80 s vs 5 s), so segment-level results are not directly comparable across agencies.
  • bUCR segment target is position-derived (50 m first-within, else closest-approach ≤200 m); holdout is day-grouped so whole trips stay within one split.
  • MBTA segment corpus is 153,498 segments / 16 days (all service-days; trip instances split by service date — see §05); the schedule baseline covers 70% of test segments.
  • Every saved model now stamps git SHA, library versions, dataset SHA-256, and seed (models/common/provenance.py); fixed-seed reruns reproduce metrics.
  • HPO (§06) tunes on the validation split only; the test set is evaluated once for the val-selected config. Seed 42, 50 TPE trials/agency, all trials recorded to scratchpad/hpo_trials_*.csv. Tuned configs are not yet promoted to the served registry.
  • Sources: docs/SESSION_2026-08-24_BUCR_ETA_MODELS.md, models/evaluation/leakage_probe.py, roadmap §3 tables.

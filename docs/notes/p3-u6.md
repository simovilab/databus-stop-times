# U6 — Serving on the pipeline

Branch `p3/u6-serve`, worktree `dst-u6-serve`. Scope: `packages/serve/**` (not
`model_loading.py`, owned by U7), `packages/serve/tests/**`, the two
hand-supplied-feature lines in `tests/e2e/test_end_to_end.py`.

## 1. Real map-matching in `default_match`

`serve/pipeline.py`'s `default_match` now actually matches, for both
observation kinds, using only public `core.spatial.polyline` primitives
(`build_polyline`, `assign_stops_monotonic`, `project_point_to_polyline`,
`upcoming_stops`) — the same primitives `core.arrivals`'s map-matched-arrival
detection is built on. I did not reuse `core.arrivals`'s internal
`_resolve_trip_geometry`/`_TripGeometry` (leading-underscore, not exported);
duplicating ~10 lines of public-API glue seemed better than importing
private core internals from another package.

- `vehicle_position`: projects the vehicle onto its trip's shape, calls
  `upcoming_stops(progress_m, ordered_stops)`, and emits one
  `MatchedObservation` per stop still ahead, each carrying a real
  `distance_to_stop` (along-shape) and `cross_track_error`. Records a
  per-item `match` error (as the old placeholder did) when there's no
  geometry, no shape for the trip, or the vehicle has passed every stop.
- `trip_update`: still passes the already-identified stop through, but when
  geometry is available it now also attaches `distance_to_stop` (the
  from-stop-to-this-stop segment length, mirroring `core.segments`'s
  feature of the same name) and `stops_ahead` (stops remaining after this
  one — the same "0 at the end" convention `core.segments` uses).

Geometry source: `ctx.static_feed` when the caller supplies one (the
contract's intended seam); otherwise `default_match` lazily loads it itself
from `ctx.source.gtfs_static_url` via `core.readers.read_static`, caching
the result (including a load failure) on `ctx.state` per run. **This
fallback exists because `stoptimes serve` (packages/cli/src/stoptimes/cli/
commands/serve.py:125) hard-codes `static_feed=None` and I can't edit
`packages/cli`** — without it, real matching would be unreachable from the
CLI entirely. When no geometry resolves at all (bad URL, no `static_feed`,
missing shapes), behavior degrades to the historical placeholder: `trip_update`
passes through with no extra fields, `vehicle_position` records an error —
so nothing that passed before regresses.

New tests: `packages/serve/tests/test_default_match_geometry.py` (5 tests,
real `GtfsStaticLoader` over a synthetic zip) prove the matching itself:
monotonic distances, correct 0-indexed `stops_ahead`, "past the last stop"
records an error, and the no-geometry fallback in both kinds.

### The e2e gate

Per the assignment, I deleted the two hand-supplied lines
(`frame["distance_to_stop"] = 300.0`, `frame["stops_ahead"] = ...`) from the
e2e test's custom `features` stage and confirmed `tests/e2e` still passes.

**Honest caveat**: in that specific test, real matching does *not* actually
fire. The e2e test's `_agency_dir` fixture sets `gtfs_static_url: unused.zip`
(a file that doesn't exist relative to the pytest cwd — confirmed), and
`ctx.static_feed` is `None` (the CLI gap above). So `default_match`'s
geometry load fails, `trip_update` observations fall through to the
no-extras path exactly as before my change, and the test only passes because
`HistoricalMeanModel.predict` (the experiment's `family: historical_mean`)
imputes missing/`NaN` group-by columns from train-fit stats rather than
raising — it was already tolerant of missing `distance_to_stop`/`stops_ahead`.
I could not close this gap without editing `packages/cli` (out of scope) or
the e2e test beyond the two permitted lines (also out of scope: the agency
fixture's `gtfs_static_url` isn't one of them). The matching code itself is
real and independently tested (above); wiring `ctx.static_feed` from the CLI
is the natural next step, for whichever track owns `packages/cli`.

## 2. `estimate_stop_times` rebuilt on the pipeline

Public signature and return shape are byte-for-byte unchanged (verified by
running the full serve suite, including the pre-existing print-style
`test_estimator.py`, `test_shape_hook.py`, `test_served_model_pin.py`,
`test_stops_ahead_alignment.py`, `test_eta_wiring.py`, plus new
characterization tests).

### Characterization tests written first

`packages/serve/tests/test_estimator_characterization.py`, run against the
*original* implementation before any change, then unchanged after. Pins:
ETA and `eta_timestamp` monotonicity with distance; the "missing vehicle
position or stops" error; an invalid `model_key`'s "Failed to load model
metadata" error; the `ewma` retirement error (per-stop, not top-level); and
`model_scope == "route"` for a route-scoped artifact. Existing files already
pinned the shape hook precedence (`test_shape_hook.py`), the pin/fallback-pin
behavior (`test_served_model_pin.py`), and the `stops_ahead` 0-indexing
(`test_stops_ahead_alignment.py`) — not duplicated here.

### What changed

1. **Model choice now goes through `core.contracts.selection.select_artifact`**
   for the route-vs-global ranking (`_select_ranked_model_key` +
   `_legacy_registry_candidates` in `estimator.py`). This replaces the old
   `prefer_route_model` if/else (try route, else global) with one call into
   the same pure selection function the pipeline uses, via a bridge that
   views the legacy `ModelRegistry`'s entries as `ArtifactMetadata` for
   ranking purposes only — **model loading is untouched**: an
   `ArtifactMetadata.artifact_id` produced here is still a legacy
   `model_key` string resolved through `_predict_with_model` exactly as
   before. The bridge's candidate-gathering filter (same `model_type` check,
   same "numeric `test_mae_seconds` present" requirement) mirrors
   `ModelRegistry.get_best_model`'s exactly, so the two can never rank a
   different candidate set.

2. **Two documented, deliberate exceptions** where I did *not* route through
   `select_artifact`, because the contract can't express the old semantics
   without changing observable behavior:
   - The served-model **pin** (`_config.served_model_key`/
     `served_model_fallback_key`) stays a direct registry-membership check.
     It's presence-only and ignores `model_type`/route entirely by design
     (an agency pin must win even over a model the ranking would score
     better) — `SelectionPolicy`'s `usable` filter requires a numeric metric
     and (optionally) a family match, which would silently exclude a pinned
     model that lacks a `test_mae_seconds` entry or doesn't match a
     `model_type` filter. Old code never applied either constraint to a pin.
   - The **last-resort fallback** (`registry.get_best_model(model_type=...)`
     with no route filter at all, reached only when neither the target
     route nor global has a candidate) stays a direct legacy call.
     `select_artifact`'s `ModelScope.matches` requires naming one specific
     route to consider `ROUTE`-scoped candidates; there's no way to ask it
     for "the best model of any route, I don't care which" the way the old
     ranking's fallback did. This is a narrow, rarely-hit edge case (also
     present, unexamined, in the pre-existing code).
   - **Known, accepted divergence**: `select_artifact`'s exact-tie tie-break
     is alphabetical by `artifact_id`; the old `list.sort` was stable
     (registry insertion order). Only matters when two candidates have the
     *identical* `test_mae_seconds` value — not exercised by any existing or
     new test, but noted here in case it ever surfaces.

3. **Structured as a thin adapter over `PipelineContext`**: the per-stop
   feature/predict loop moved, unchanged, into `_stage_match_and_features`
   and `_stage_predict`, threaded through a real `stoptimes.core.contracts.
   pipeline.PipelineContext` (`ctx.now`, `ctx.model`, `ctx.static_feed`).
   This is *not* literally `StoptimesPipeline.run()` / `default_match` /
   `default_predict` from `serve/pipeline.py` — the estimator's contract
   (databus hands it already-matched `upcoming_stops`, optionally with a
   per-stop `shape_distance_to_stop` override or a preloaded `ShapePolyline`)
   doesn't fit `default_match`'s job (autonomous matching against a static
   feed). Forcing that fit would have meant dropping the
   `shape_distance_to_stop` override path and the `shape=` `ShapePolyline`
   hook — an actual behavior change on the exact seam databus relies on. So
   the adapter keeps its own small match+features/predict split, in the same
   six-stage spirit, without a second reimplementation of either the
   feature math (unchanged, just relocated) or model lookup (now shared via
   `select_artifact`).

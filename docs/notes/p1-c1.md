## Decisions worth flagging to the orchestrator / Phase 2 tracks

- **`examples/` didn't exist yet.** Created `examples/experiments/` (owned by
  C1). `examples/agencies/` does not exist — that's C2's move target for the
  val source YAMLs. `test_contract_source.py` checks both
  `packages/val/.../config/sources/` and `examples/agencies/` and uses
  whichever has files, so it survives C2's move without edits on my side.
- **val source YAML stays flat, unmodified.** Rather than widen `Source`
  with legacy fields (the PLAN allowed either), C1 used the explicit
  `contracts.adapters.source_from_val_yaml` adapter, since it keeps `Source`
  itself as the one shape every *new* caller targets. If C2 wants callers to
  write the rich `Source` shape directly to `examples/agencies/*.yaml`
  instead of the flat shape, that's a C2 call — the adapter still works on
  the flat shape either way.
- **`core/contracts/adapters.py` cannot import `stoptimes.record`** (core is
  upstream of record — docs/PLAN.md rule 1). The row-level adapters
  (`observation_from_vp_row`/`observation_from_tu_row`) take a plain
  `Mapping` documented to match `record.storage.schema`/`tu_schema` column
  names by name, not by import. T5 (record) or T1 (data) call these with a
  `pandas.Series`/dict from their own DataFrames — nothing here reads those
  modules directly.
- **One `Experiment` = one `ModelSpec`.** A `--models a b c` sweep (today's
  `train_all_models.py`) becomes multiple `Experiment` files/objects, not a
  `list[ModelSpec]` field. Flagged as an open question in CONTRACTS.md in
  case T3/U1 want it differently.
- **pandas 3.0.5 is installed in this worktree's venv** (not 2.x as the
  `pyproject.toml` floor of `>=2.2` might suggest). `pd.to_datetime` on a
  plain Python string list now defaults to `StringDtype` for object columns
  and needs explicit `.dt.as_unit("ns")` after `utc=True` to land on
  `datetime64[ns, UTC]` rather than a coarser unit — confirmed empirically
  and is exactly what `contracts.data.coerce_utc_ns` does. Verified against
  the actual installed version rather than assuming the pyproject floor.

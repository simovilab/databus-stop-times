# P1 C2 — de-SIMOVI config

Track notes for the orchestrator. Owned paths per docs/PLAN.md §5 C2:
`packages/core/src/stoptimes/core/config.py` (+ tests), the agency-constant
call sites in `packages/serve/src/stoptimes/serve/estimator.py` and
`packages/train/src/stoptimes/train/datasets/dataset_builder.py`,
`packages/val/src/stoptimes/val/config/**`, `packages/val/src/stoptimes/val/feeds/source_config.py`,
val source/CLI-`sources` tests, `examples/agencies/**`.

## What moved

- `AGENCY_TEMPORAL_DEFAULTS` / `AGENCY_MODEL_DEFAULTS` / `DEFAULT_AGENCY`'s
  hardcoded data now lives in `examples/agencies/<agency>.yaml` (one file per
  agency, shared with `stoptimes.val`'s source configs — `git mv`'d from
  `packages/val/src/stoptimes/val/config/sources/*.yaml`).
- `packages/core/src/stoptimes/core/config.py`: `ProjectConfig.default_timezone`
  / `.default_region` / `.served_model_key` / `.served_model_fallback_key`
  now resolve, in order: explicit env var → the active agency's profile file
  (`STOPTIMES_AGENCY_FILE` or `STOPTIMES_AGENCY`/`ETA_AGENCY` looked up via
  the new `sources_search_path()`) → generic defaults (`UTC`, no region, no
  pin).
- `AGENCY_TEMPORAL_DEFAULTS` / `AGENCY_MODEL_DEFAULTS` are kept as
  module-level names (now `Mapping` views over the same profile-file
  resolution) so direct-index call sites I don't own —
  `packages/core/src/stoptimes/core/segments.py` (`resolve_agency_temporal`)
  and its tests — keep working unmodified. Confirmed via
  `grep -rn "AGENCY_MODEL_DEFAULTS\|AGENCY_TEMPORAL_DEFAULTS\|DEFAULT_AGENCY" packages/`
  that no other call sites exist beyond these plus my two owned ones.
- New shared resolver: `stoptimes.core.config.sources_search_path(explicit=None)`
  → `[explicit]` or `STOPTIMES_SOURCES` (`os.pathsep`-separated) or
  `./examples/agencies` under cwd. Used by both the agency-profile lookup
  above and `stoptimes.val.feeds.source_config.list_sources`/`load_named_source`.

## Deprecated, kept working

- `ETA_AGENCY`, `ETA_TIMEZONE`, `ETA_HOLIDAY_REGION`, `ETA_MODEL_KEY`,
  `ETA_MODEL_FALLBACK_KEY`, `MODEL_REGISTRY_DIR` still work, each via a
  `_read_env(new, old)` helper that emits `DeprecationWarning` when only the
  old name is set. New env vars: `STOPTIMES_AGENCY`, `STOPTIMES_AGENCY_FILE`,
  `STOPTIMES_TIMEZONE`, `STOPTIMES_HOLIDAY_REGION`, `STOPTIMES_MODEL_KEY`,
  `STOPTIMES_MODEL_FALLBACK_KEY`, `STOPTIMES_MODEL_REGISTRY_DIR`,
  `STOPTIMES_SOURCES`.
- `set_model_registry_dir()` now writes both `STOPTIMES_MODEL_REGISTRY_DIR`
  and the deprecated `MODEL_REGISTRY_DIR` to `os.environ`, because
  `stoptimes.models.common.registry` and
  `stoptimes.val.predictors.gtfs_eta_models` (both outside my owned paths)
  read `os.environ["MODEL_REGISTRY_DIR"]` directly rather than through
  `ProjectConfig`. **Gap**: a deployment that sets only
  `STOPTIMES_MODEL_REGISTRY_DIR` (never touching the old name, never calling
  `set_model_registry_dir()`) won't be seen by those two modules. Low risk
  today (nothing sets the new name in production yet) but worth a follow-up
  pass over those two files in a later phase — I did not touch them since
  they're not on my owned-paths list.
- **`_LEGACY_BUILTIN_PROFILES`** in `config.py`: a deliberately small,
  clearly-marked, deprecated fallback table (`mbta`/`bucr` only) used *only*
  when no profile file is found anywhere on `sources_search_path()`. This
  keeps SIMOVI's production databus/VPS deploys — which set `ETA_AGENCY=bucr`
  today with no `examples/agencies/` checked out alongside them — serving the
  same pinned bUCR model as before, unchanged. Emits `DeprecationWarning` on
  every use; delete in Phase 4 per docs/PLAN.md §8 G1, once every deployment
  ships a real profile file (or `STOPTIMES_AGENCY_FILE`/`STOPTIMES_SOURCES`
  pointing at one). Test: `test_legacy_builtin_bucr_pin_used_when_no_profile_file_found`
  in `packages/core/tests/test_core.py`.

## val sources / CLI

- `packages/val/src/stoptimes/val/feeds/source_config.py`: `list_sources`/
  `load_named_source` now search every directory from `sources_search_path()`
  (merging results) instead of one hardcoded package-relative dir; a missing
  named source raises `FileNotFoundError` listing every directory searched.
  `SourceConfig` (pydantic, default `extra="ignore"`) silently tolerates the
  new agency-profile-only keys (`timezone`, `holiday_region`, `serving`) in
  the same file — verified, no model change needed.
- Added `--sources-dir` to the val CLI's `sources` command
  (`packages/val/src/stoptimes/val/cli/main.py`) so it can search a directory
  exclusively. **Scope note**: `cli/main.py` isn't on my owned-paths list,
  but the task explicitly asked for "search path: `--sources-dir` option
  (where the val CLI takes it)"; I made the smallest possible change (one
  command, additive `Option`, no other command touched) rather than skip it.
  Flagging in case the orchestrator wants it re-reviewed by whichever track
  owns `cli/main.py` generally.
- `api/app.py`, `api/runs.py`, other CLI commands (`run`, etc.) all call
  `list_sources()`/`load_named_source(name)` with no args — unchanged, still
  works via the default search path (cwd-relative `./examples/agencies`),
  same as before this track's changes just pointed at a different default
  directory. Not edited (not owned, and no signature change was needed).
- Test cwd-independence: `packages/val/tests/test_feeds.py` and
  `packages/val/tests/test_cli.py`'s `sources` tests now pass an explicit
  `config_dir`/`--sources-dir` computed from `Path(__file__).resolve().parents[3]`
  rather than relying on cwd. **Not changed** (out of scope, not the
  sources/CLI-sources tests): `packages/val/tests/test_api.py`'s `/api/sources`
  and `/api/runs` tests still rely on cwd == repo root (inherited from
  `api/app.py`/`api/runs.py` calling with no args) — same assumption the test
  suite already made before this track; flagging since the task called out
  cwd-independence as a goal for the sources-related tests I do own.

## Model files

- `packages/train/src/stoptimes/train/datasets/dataset_builder.py` and
  `packages/serve/src/stoptimes/serve/estimator.py`: no logic changes, only
  comments/docstrings updated to point at profile files instead of the old
  hardcoded tables (they already went through `AGENCY_TEMPORAL_DEFAULTS[...]`
  / `_config.default_timezone` etc., which keep working unchanged).

## Anything unsure

- Whether `cli/main.py`'s `sources` command edit should have instead been
  left to whichever track ends up owning `packages/val/src/stoptimes/val/cli/**`
  generally (T6 in Phase 2) — see note above.
- `default_region`'s type changed from `str` to `Optional[str]` (a generic
  agency with no `holiday_region` now legitimately has none, vs. previously
  a `KeyError` for any agency outside the hardcoded mbta/bucr pair). This is
  strictly more permissive than before, not a behavior regression for
  mbta/bucr, but downstream code that assumes `default_region` is always a
  non-empty string (e.g. `core/features/temporal.py`'s
  `_get_holiday_calendar(region: str)` calling `.upper()`) would `AttributeError`
  on `None` for a brand-new agency with no profile and no legacy entry. Not
  fixed here (`core/features/temporal.py` isn't on my owned-paths list) —
  flagging for whichever Phase-2 track touches it.

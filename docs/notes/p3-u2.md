# Phase 3, track U2 — CLI polish

## Startup time (docs/PLAN.md §7, U2 acceptance: `--help` under 300ms)

Measured with `python -X importtime` and wall-clock `time`, in the worktree's venv (Python 3.12).

**Before** (baseline, `main` at branch point):

| command | time |
|---|---|
| `stoptimes --help` | ~3.0-4.9s (worse cold, ~3s warm) |
| `stoptimes val --help` | same — `val.mount()` imported `stoptimes.val.cli.main` eagerly at CLI-assembly time, every invocation |
| `stoptimes data/record/train/models/serve --help` | ~0.4-0.5s — mostly `typer`'s own rich-markdown help formatter |

Root cause #1 (the ~3s one): `stoptimes.val.cli.main` imports `stoptimes.val.engine.assembly`
at module scope, which imports `stoptimes.val.predictors.gtfs_eta_models` ->
`stoptimes.serve.estimator` -> `stoptimes.models.common.registry` -> `stoptimes.models.common.metrics`
-> `sklearn.metrics` (~1.9s), and separately `stoptimes.val.figures` -> `matplotlib.pyplot` (~0.6s).
All of that lives in `packages/val` and `packages/models`, outside this track's owned paths.

Root cause #2 (the ~150-200ms one, present on every `--help`): typer's rich-formatted help
(`typer.rich_utils`) imports `rich.markdown` -> `markdown_it` lazily, but on first `--help`
invocation, every time.

**After:**

| command | time |
|---|---|
| `stoptimes --help` | ~0.24s |
| `stoptimes val --help` | ~0.24-0.26s |
| `stoptimes data/record/train/models/serve --help` | ~0.22-0.26s |

Fixes:
1. `main.py`: `typer.Typer(..., rich_markup_mode=None)` on the top-level app. This disables
   typer's rich/markdown help renderer (falls back to click's plain formatter) and avoids the
   `rich.markdown`/`markdown_it` import on every `--help`. Sub-`Typer`s inherit this from the
   parent (confirmed empirically), so it only needed setting once.
2. `commands/val.py`: rewritten so `val.mount()` never imports `stoptimes.val.cli.main` at
   mount time. The seven real val commands (`version`, `sources`, `run`, `replay`, `report`,
   `walk-forward`, `figures`) are registered as `context_settings=PASSTHROUGH` forwarding stubs
   — the same pattern this codebase already used for `record compact` / `models check` /
   `train legacy-all` — with a static one-line `help=` string. The stub's body imports the real
   module and forwards `ctx.args` to the real click command's `.main()` only when the
   subcommand is actually invoked. `api`/`tui` are unchanged (they were already lazy). This
   keeps `stoptimes val --help` static/fast; `stoptimes val run --help` (or any other leaf
   subcommand's own `--help`) still pays the real import cost, same as `record compact --help`
   already did — that's outside the group-`--help` budget this track owns.
3. Added `packages/cli/tests/test_cli_startup.py`: a real subprocess/wall-clock test
   (`python -m stoptimes.cli.main <group> --help`, best of 3 runs) asserting `< 0.3s` for the
   top-level help and every group (`data`, `record`, `train`, `models`, `serve`, `val`).
   `runner.invoke` (in-process CliRunner) was deliberately not used for this test — it reuses
   the already-imported interpreter and wouldn't catch an import-time regression.

**Follow-up for whoever owns `packages/val` / `packages/models` next:** the deeper fix is to
make `stoptimes.val.engine.assembly`'s predictor registration lazy (defer the
`GtfsEtaModelPredictor` import, which is what pulls in `sklearn` via `stoptimes.models.common.metrics`),
and `stoptimes.val.figures`'s `matplotlib.pyplot` import lazy (move inside the function bodies
that actually render figures). Once that's done, `commands/val.py`'s forwarding-stub workaround
could be simplified back to a plain `app.add_typer(module.app, ...)` mount, though there's no
harm in leaving it as-is.

## `--json` audit

Added `--json` (or documented existing shapes) where missing:
- `train run` (trained-artifact success path; `--dry-run` already printed JSON)
- `models card`, `models promote`
- `record start`
- Added/completed JSON-shape docstrings on: `data list`, `data inspect`, `data remove`,
  `data add`, `data arrivals`, `data frame`, `record status`, `models list`, `serve`.

Existing JSON shapes were left untouched (contract: "keep existing JSON shapes stable").

## Consistent presentation

Added `stoptimes.cli._util.print_table` / `error` / `warn` / `success` — shared helpers so
table rendering and success/error/warning styling don't have to be reimplemented per command.
Wired `print_table` into `data list`, `data inspect`, and `models list` (the latter previously
hand-formatted a fixed-width string table instead of using `rich`, like everywhere else).
`error`/`warn`/`success` are defined but not yet swept through every existing `typer.secho`
call site — that would be a larger, higher-risk mechanical pass across every command; left for
a follow-up since existing call sites are already consistent in spirit (`✗ ...` red/stderr,
`✓ ...` green, `⚠ ...` yellow/stderr) even where they don't go through the shared function yet.

## Install hints

Audited every command; all commands belonging to an optional part (`record`, `train`, `serve`,
`val`, and `stoptimes.models`) already call `stoptimes.cli._util.require(module, extra)` before
their first optional import — this predates this track. `val`'s fallback (`stoptimes.val` not
installed at all) still goes through `require()` via `val_missing`.

**Found, not fixed (outside owned paths):** `models.py`'s `require("stoptimes.models", "core")`
calls print `pip install 'stoptimes[core]'`, but `packages/cli/pyproject.toml`'s `core` extra
only pulls `stoptimes-core`, not `stoptimes-models` — `packages/core/pyproject.toml` has no
dependency on `stoptimes-models` either. So that install hint is currently wrong: installing
`stoptimes[core]` does not actually make `stoptimes.models` importable. This predates this
track (the `require()` call sites weren't touched, only surrounding `--json` additions).
**Dependency need:** either add a `models = ["stoptimes-models"]` extra to
`packages/cli/pyproject.toml` and change `models.py`'s four `require("stoptimes.models", "core")`
calls to `require("stoptimes.models", "models")`, or fold `stoptimes-models` into the `core`
extra's dependency, whichever matches the intended install-parts story. I did not touch
`pyproject.toml` per instructions.

## Uncertain / flagged for the orchestrator

- The `val` command-forwarding rewrite is a genuine (if standard-pattern) architectural change
  to how `val` is mounted, not a one-line fix — it was the only way to hit the 300ms budget for
  `stoptimes val --help` without editing `packages/val`/`packages/models`. Behavior is
  unchanged (proven by the passing e2e test and `packages/cli/tests/test_cli.py`'s existing
  `val` tests), but it's worth a second look given its size relative to the rest of this track.
- `error`/`warn`/`success` helpers in `_util.py` exist but aren't yet used everywhere — a
  follow-up track or a dedicated pass could sweep them through the remaining `typer.secho`
  call sites for full consistency.

## Dependency needed: `textual` as an optional extra of `stoptimes-train`

Per the track brief, `packages/train/pyproject.toml` was not touched (not an
owned path). `stoptimes.train.tui.app` (and only that module) imports
Textual; `stoptimes.train.tui.registries`/`builder` and `stoptimes.train`
itself do not, and were verified (locally, by blocking `import textual` at
the `builtins.__import__` level) to import fine without it installed.
`packages/cli/src/stoptimes/cli/commands/train.py`'s `train ui` command
guards with `importlib.util.find_spec("textual")` before ever importing
`stoptimes.train.tui.app`, giving an install hint instead of a traceback.

**Ask for the orchestrator**: add to `packages/train/pyproject.toml`:

```toml
[project.optional-dependencies]
tui = ["textual>=0.85"]
```

`textual>=0.85` (version `8.2.8` resolved) is already in `uv.lock` — both
`legacy/etaval` and `packages/val` already depend on it — so this should
relock without pulling a new package, just a new edge from `stoptimes-train`
extras to the existing lock entry.

## No model-family registry exists yet — `registries.list_model_families()` reads
## `contract_adapter`'s private maps instead of redeclaring the name list

`stoptimes.models.common.contract_adapter.get_model_class` is the only real
source of truth for which family names resolve to a trainable model
(`_FAMILY_FACTORIES`, `_BASELINE_FACTORIES`, plus the special-cased
`"lstm"`), but it's private, and neither it nor anything else exposes
descriptions or hyperparameter metadata for the TUI to show. Per the track
brief ("If a registry does not exist yet, add a thin accessor in your own
package rather than hardcoding"), `stoptimes.train.tui.registries` does two
things instead of hand-copying a family list:

1. Reads `contract_adapter._FAMILY_FACTORIES` / `_BASELINE_FACTORIES`
   directly (with a `# noqa: SLF001` and a docstring explaining why) so the
   set of selectable family names can never drift from what
   `get_model_class` actually accepts — there is no second, independently
   maintained list of family names anywhere in this track's code.
2. Introspects each family's real `__init__` signature (`inspect.signature`)
   for parameter names, defaults, and types, rather than hand-copying
   `max_depth: int = 5` etc. — if a family's constructor changes, the TUI's
   defaults change with it automatically. `lstm` is introspected from
   `train_lstm`'s signature filtered to `LSTMModelAdapter._LSTM_FIT_KWARGS`
   (also read directly off the class, same reasoning); if `torch` isn't
   installed the import fails and the family still appears (a valid
   `ModelSpec.family` value even before you can actually train it locally)
   with `type_hint="unknown"` params instead of crashing.

Only the human-readable descriptions (family summaries, per-parameter
descriptions) are authored text in `registries.py` — there is nowhere else
in the codebase that carries them, and none of the family classes have
per-argument docstrings a machine could reliably extract.

**Ask for the orchestrator / a future track**: `stoptimes-models` should grow
a small public `list_families()` (name, description, param schema) of its
own; `stoptimes.train.tui.registries.list_model_families` should then become
a thin re-export of that instead of reading contract_adapter's private
attributes. Flagging rather than doing it here since `packages/models` is
outside this track's owned paths.

## No target registry exists either

`contracts.experiment.Experiment.target` is a free `str`
(default `"arrival_delay_s"`), validated by nothing beyond "is a string."
The only other name with any meaning anywhere is the legacy alias
`train.experiment._LEGACY_TARGET_COLUMN` ("time_to_arrival_seconds"), which
`_resolve_target_column` falls back to when a dataset doesn't have
`arrival_delay_s`. `registries.list_targets()` offers both, described; the
TUI's Data & target tab also has a free-text override input since the
contract doesn't restrict the value. No accessor gap to flag beyond "this
registry doesn't exist yet" — there's nothing upstream to read from.

## Hyperparameter tuning ranges (`ParamRange`/`ParamChoices`)

`contracts.experiment.ParamValue` already supports `ParamRange` (low/high/
step/log) and `ParamChoices` (a discrete list) alongside plain scalars —
`builder.py` round-trips both through `write_draft`/`load_experiment`
(see `test_builder.py::test_param_range_and_choices_survive_the_round_trip`)
and exposes `make_param_range`/`make_param_choices` helpers. The TUI's
compact `name=value` hyperparameter input field (Model tab) only accepts
scalars today — building a range/choices value requires calling the
`ExperimentDraft.params` dict directly (e.g. from a script, or a future
richer per-parameter widget). Flagging as a follow-up: give each introspected
`ParamInfo` (registries.py already marks `tunable: bool` per parameter) its
own small "fixed value / range / choices" sub-form in the Model tab, instead
of the one-line text field.

## `ScheduleBaseline`/`ConstantSpeedBaseline` have no constructor params —
## not a gap, just confirmed by `list_baselines()`'s tests

Both baseline classes take no `__init__` arguments (`ConstantSpeedBaseline`
fits its one internal `speed_m_s` from data, not a hyperparameter a user
sets), so `ModelFamilyInfo.params` is intentionally empty for both.

## Test coverage (`packages/train/tests/tui/`)

- `test_registries.py`: family/baseline name set matches
  `get_model_class`'s accepted names (imports it directly rather than
  duplicating the list), every family/baseline/feature/target has a
  description, `xgb`'s introspected params match its real signature
  (`max_depth` default `5`, tunable).
- `test_builder.py`: validation reports every problem at once (not just the
  first), unknown feature names are caught before `write_draft` touches the
  filesystem, `to_experiment`/`from_experiment` round-trip losslessly,
  `write_draft` both round-trips through `load_experiment` and refuses to
  write an invalid draft (file never created), opening a shipped example
  (`examples/experiments/xgb-baseline.yaml`) reproduces it exactly,
  edit-then-resave preserves untouched fields, and `ParamRange`/
  `ParamChoices` survive the round trip.
- `test_app.py`: three Textual `run_test()`/pilot smoke tests (per the
  track brief's "at most a couple") — the app mounts with all tabs present,
  filling in the minimum fields (name, source, family) and pressing Save
  writes a file `load_experiment` accepts, and opening an existing
  experiment.yaml pre-fills the form. Guarded with
  `pytest.importorskip("textual")` so the file doesn't error out if the
  extra genuinely isn't installed in some future environment.

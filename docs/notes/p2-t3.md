# P2-T3 notes (train)

## Cross-track: `load_dataset` fixture-path fix breaks `packages/serve/tests/test_eta_wiring.py`

Deliverable 6 (Phase-1 follow-up) required removing
`stoptimes.models.common.data._default_dataset_search_paths`'s fallback into
`packages/serve/tests/fixtures/` — production code must not know another
package's test paths. Done: the resolver now checks `STOPTIMES_DATASET_DIR`
then `./datasets/{name}.parquet`, nothing else. `packages/models/tests/`
picked up its own copy of the fixture (`packages/models/tests/fixtures/sample.parquet`)
plus a `conftest.py` that sets `STOPTIMES_DATASET_DIR` for every test in that
package (autouse fixture) — `packages/models` tests are green.

**Not fixed (outside owned paths):** `packages/serve/tests/test_eta_wiring.py`
calls `load_dataset("sample")` with no `dataset_dir`, relying on the removed
fallback. It now fails with `FileNotFoundError` (4 tests). `serve/**` is T4's
territory, so I didn't touch it. The fix is mechanical and safe: add a
`packages/serve/tests/conftest.py` mirroring the one added here — an autouse
fixture setting `STOPTIMES_DATASET_DIR` to `packages/serve/tests/fixtures/`
(the fixture file itself doesn't need to move). T4/orchestrator should apply
this before merging, or accept the 4 failures until then.

## Cross-track seam: `train.experiment.resolve_dataset` has no catalog to call

`Experiment.data.sources` (raw source/agency ids, meant to route through T1's
local data catalog) has no resolver yet — T1's `core/catalog/**` doesn't
exist on this branch. `resolve_dataset()` raises `NotImplementedError` naming
exactly this when `sources` is given with no `datasets`. Today, every
experiment must go through `data.datasets: [<name>]`, resolved via
`stoptimes.models.common.data.load_dataset` (the same lookup every model
family's own `train_*` function already uses). Once T1's catalog exists,
extend `resolve_dataset` — it's the one function that needs it.

## `ModelSpec.params` can't carry a list — how `historical_mean`/`ewma`'s `group_by` is handled

`contracts.experiment.ParamValue` is `float | int | str | bool | ParamRange |
ParamChoices` — no list. `historical_mean`/`ewma`'s natural hyperparameter,
`group_by: list[str]`, can't be set through `ModelSpec.params`. Rather than
special-case those two families in the experiment runner,
`FamilyModelAdapter.fit` (packages/models/src/stoptimes/models/common/contract_adapter.py)
sets `inner.group_by = list(X.columns)` whenever the wrapped model has that
attribute, before calling its own `fit`. In practice this means: whatever
columns `Experiment.features` selects *is* the grouping key for these two
families — matches the shipped `examples/experiments/historical-mean-kfold.yaml`
(`features: [route_id, stop_sequence, hour, day_of_week, is_peak_hour]`,
no `group_by` param) without any special orchestrator-side plumbing. Flagging
this for sign-off in case a future family needs a genuinely list-valued
hyperparameter that *isn't* just "the feature list" — the contract would need
a list arm on `ParamValue`.

## `split.kind: "kfold"` and `"trip"` — simplifications

- **kfold**: one `Experiment` trains one model (contracts.experiment's
  explicit design choice), so a true k-fold *rotation* (`n_folds` models)
  doesn't fit. `split_dataset` reports one held-out fold — the last
  `1/n_folds` of rows, time-ordered — as the test set, the rest as train.
  Noted in the artifact's card under "Notes".
- **trip**: routed through `ETADataset.temporal_split(purge=True,
  service_offset_h=7)` (MBTA's offset). No per-agency offset is plumbed in at
  this layer yet (`Experiment`/`DataSelection` don't carry it) — a real
  bUCR-vs-MBTA run needs this parameterized once an agency profile is
  threaded through `run_experiment`.
- Both **time** and **trip** always fold their validation slice back into
  train (`Model` has no separate val split in the contract); `lstm`'s adapter
  carves its own validation window back out of `X`/`y` for early stopping.

## `Experiment.target` default (`arrival_delay_s`) vs. shipped datasets (`time_to_arrival_seconds`)

No shipped dataset has an `arrival_delay_s` column yet (that's the eventual
`Arrival`-contract-derived target; today's datasets are pre-contract
`ETADataset` output). `_resolve_target_column` in `train/experiment.py` falls
back from `arrival_delay_s` to `time_to_arrival_seconds` when the former
isn't present, so the contract's default target works against today's data
without every experiment.yaml needing `target: time_to_arrival_seconds`
spelled out. Once T1/T2 ship a real `arrival_delay_s` column, this fallback
becomes a no-op (the real column wins) rather than needing removal.

## Feature registry: one entry per output column, not per feature group

`core/features/registry.py` registers one `Feature` per dataset column
(`distance_to_stop`, `hour_sin`, `route_id`, ...), matching how
`examples/experiments/*.yaml` (signed off in Phase 1) list `features` —
fine-grained column names, not `ETADataset.FEATURE_GROUPS`-style bundles. All
non-temporal entries are validated passthroughs over columns already
materialized by `train.datasets.dataset_builder` /
`segment_dataset_builder` / `rolling_conditions` — `core` can't import
`train` (docs/PLAN.md rule 1), so the registry documents provenance in each
`Feature.source` string rather than calling that code. `serve` (T4) computing
these features live from a vehicle position is a real future need this
doesn't address yet — worth a look when T4 builds its `features` pipeline
stage.

## `stoptimes models promote` writes into `examples/agencies/<source>.yaml`

`--sources-dir` (default `STOPTIMES_SOURCES` env var, else `./examples/agencies`)
picks the agency profile file, matching the lookup order documented in
`docs/CONTRACTS.md` §1. Writes `serving.selection.pins[<--as>]` via a plain
`yaml.safe_load`/`safe_dump` round-trip (not `Source.model_validate`, since a
profile file's flat val-shape only becomes a `Source` through
`source_from_val_yaml` — writing back through the adapter's inverse wasn't
built, so this edits the raw YAML dict directly and preserves every other
key). Refuses if the artifact id isn't in `--registry`.

## Shared `packages/cli/tests/test_cli.py` — `train run` / `models card` stay "planned" with no argument

Both commands accept an **optional** positional argument now
(`experiment_path` / `artifact_id`); calling them with **no** argument still
falls through to `planned(...)` (exit 2, "Phase 2 ..." in output) —
`test_train_run_is_planned` and `test_models_card_is_planned` in the shared
`test_cli.py` (not edited, per instructions) still pass unmodified. Real
behavior (loading an experiment.yaml / rendering a card) only triggers when
an argument is given, covered in the new `packages/cli/tests/test_cli_train.py`.

## `stoptimes models list --json` output shape

Not specified anywhere in `docs/CONTRACTS.md` (only the table columns are
named in the track brief: scope, metric, created). Chose:
`[{"artifact_id", "family", "scope", "routes", "metric", "created"}, ...]`,
one dict per artifact, `metric` = `metrics["test_mae_seconds"]` (the
`selection` contract's default metric key) or `null`. Flagging in case
Phase 3's TUI wants a different shape — cheap to change now, before anything
depends on it.

# U7 — Registry lifecycle: notes

## What was built

1. **Version-drift refusal** (`packages/serve/src/stoptimes/serve/model_loading.py`):
   `check_version_drift()` calls the existing `contracts.artifact.version_mismatches`
   and refuses (`ArtifactVersionDriftError`) when a load-critical library
   (`sklearn`/`xgboost` for pickle, `xgboost` for xgboost-json, `onnxruntime`
   for onnx, `torch` for torchscript — `LOAD_CRITICAL_LIBS`) has drifted.
   Override via `STOPTIMES_ALLOW_VERSION_DRIFT` env var (`all`/`1`/`true`/`*`
   or a comma-separated artifact-id list) or `load_artifact_model(...,
   allow_version_drift=True)`. Wired into `load_artifact_model`, called
   before any file is opened.

2. **Promote/rollback** (`packages/models/src/stoptimes/models/common/promotion.py`
   + `packages/cli/src/stoptimes/cli/commands/models.py`): the pin an operator
   promotes into is unchanged (`serving.selection.pins` in the agency profile
   YAML). A sidecar `<source>.promotions.json` next to the profile records
   history per pin key so `models rollback` can undo a promotion. New CLI
   commands: `rollback`, `pins`. `promote` now also writes to the sidecar.

## Things I was unsure about / flagged rather than guessed

- **`lib_versions` key names.** `models/common/provenance.py::lib_versions()`
  uses the import name `"sklearn"` (not `"scikit-learn"`) as the dict key —
  that's what actually gets written into `provenance.lib_versions` by every
  real training run today. `packages/core/tests/test_contract_artifact.py`'s
  own fixture happens to use `"scikit-learn"` as a made-up example key for
  `version_mismatches` — that's just test data for a generic comparison
  function, not a claim about the real key name. `LOAD_CRITICAL_LIBS` and my
  tests use `"sklearn"` to match the real producer. If a future track
  renames the provenance key, `LOAD_CRITICAL_LIBS`' keys need to move with
  it — nothing enforces the two stay in sync today (they live in different
  packages: `core` vs `serve`).

- **onnx/torch drift is currently undetectable.** `LOAD_CRITICAL_LIBS`
  declares `onnxruntime`/`torch` as load-critical for their formats, but
  `provenance.lib_versions()` (models package) only ever records
  `python`/`sklearn`/`xgboost`/`numpy`/`pandas` — it never records
  `onnxruntime`/`torch`. So a drift in either currently can't be detected
  (the dict lookup in `version_mismatches` just skips libraries not present
  in `installed`/`meta.provenance.lib_versions`). This isn't a regression —
  onnx/torchscript loading isn't wired into `load_artifact_model` at all yet
  (`NotImplementedError`) — but whoever wires it up should also extend
  provenance recording for that family, or the refusal will silently never
  fire for those formats. Filed here rather than touching `models/common/provenance.py`'s
  caller list of libraries speculatively.

- **Didn't touch `packages/core`.** The task correctly predicted
  `version_mismatches` needs no changes — it was already exactly what a
  caller needs (list of `"lib: built X, installed Y"` strings). All new
  logic (which libs are load-critical, the override, the sidecar history)
  lives in owned files.

- **`test_cli_train.py` already covers `models list`/`card`/`promote`
  basics** (a different track's file, not matched by my `test_cli_models*.py`
  glob). I left it untouched and added `test_cli_models_promote.py` for the
  U7-specific behavior (history retention, rollback, pins) rather than
  duplicating or editing someone else's file.
